# SCHEMA — taxonomy ของสมอง (agent อ่านไฟล์นี้ก่อนเขียนความรู้ทุกครั้ง)

> ผู้ใช้ไม่ต้องรู้จักไฟล์นี้ — เรียก `/sb` คำเดียว agent เป็นคน route ตามกติกาข้างล่าง
> อิง Karpathy LLM Wiki (via Paul Kimmy) ปรับให้เรียบง่าย: 4 ลิ้นชักความรู้ ไม่มีถังรวม

## ลิ้นชักความรู้ (เลือกได้ลิ้นชักเดียวต่อ 1 node)

| โฟลเดอร์ | เก็บอะไร | ตัวอย่างไฟล์ |
|---|---|---|
| `entities/` | บริษัท / เครื่องมือ / ผลิตภัณฑ์ / บุคคลสาธารณะในฐานะ "หัวข้อ" | `higgs-field.md`, `andrej-karpathy.md` |
| `concepts/` | แนวคิด / เทคนิค / pattern **รวมถึงหน้า topic-synthesis และ overview** — "หัวข้อกว้าง" คือ concept node ใหญ่ ไม่มีถังแยก | `llm-wiki.md`, `format-dna-extraction.md`, `humanoid-robots-2026.md` |
| `Magic/` | วิชาไสยเวทย์ที่เจ้าของร่ำเรียนและใช้จริง เช่น คาถา มนต์ และพิธี | `คลังวิชาไสยเวทย์.md`, `โองการชุมนุมครู.md` |
| `comparisons/` | หน้าเทียบ A vs B (สองสิ่งขึ้นไป ชั่งน้ำหนักกัน) | `indexnow-vs-google-indexing.md` |
| `queries/` | **คำถาม research ที่ตอบแล้ว** — เก็บคำตอบเป็น node ถาวร คำถามเชิง "X คืออะไร/ควรใช้อะไร/ทำยังไง" ที่สังเคราะห์ข้ามหลาย source | `how-to-persist-agent-memory.md` |

**ไม่ใช่ลิ้นชักความรู้** (มีเจ้าของ op อยู่แล้ว — อย่าเขียนปน):
`people/` = CRM คนรู้จักจริงที่มี relationship (op PERSON) · `journal/` = บันทึกส่วนตัว ·
`raw/` = ต้นฉบับ immutable · `output/` = deliverables ที่สร้างจาก vault · `audit/` = ผล AUDIT

## กติกาการเขียน (บังคับทุก node)

1. **Search-then-update, create-last.** ก่อนสร้างไฟล์ใหม่: grep ทั้ง `aliases:` และเนื้อ node
   เดิมในทุกลิ้นชัก — ถ้าทับซ้อน ให้**ขยาย node เดิม** ไม่สร้างไฟล์ใกล้เคียงเพิ่ม
   (node ซ้ำคือสิ่งที่ทำให้กราฟเสื่อมเร็วที่สุด)
2. **ชื่อไฟล์**: ก่อนสร้าง node จาก `/sb` ต้องเสนอชื่อไฟล์ทั้งสองแบบแก่เจ้าของและรอคำตอบเสมอ: `ไทย: <ชื่อไทย>.md` และ `ENG: <english-kebab-case>.md` แล้วใช้เฉพาะแบบที่เจ้าของเลือก. ข้อยกเว้น: `raw/`, `journal/`, `audit/` ใช้รูปแบบวันที่ที่กำหนดไว้ และการแก้ node เดิมใช้ชื่อเดิม.
3. **เนื้อหา**: สรุปภาษาไทย ศัพท์เทคนิคอังกฤษคงไว้ quote ต้นฉบับตามภาษาเดิม
4. **Frontmatter** (ทุก type เหมือนกัน):
   ```yaml
   ---
   title: <ชื่ออ่านง่าย>
   aliases: [คำพ้องไทย, English synonyms]   # REQUIRED — คือสิ่งที่ทำให้ค้นเจอ
   updated: YYYY-MM-DD
   sources: [raw file names หรือ URL/ที่มา]
   ---
   ```
5. **Wikilinks**: ลิงก์ `[[node-อื่น]]` ที่เกี่ยวข้องเสมอ (ข้ามลิ้นชักได้ ใช้ชื่อไฟล์ไม่ต้องใส่ path)
   - ทุก node ที่สร้างหรือแก้ต้องมีอย่างน้อย 1 ลิงก์แบบ non-self ที่ resolve ไปยังไฟล์จริงใน vault
   - ห้ามสร้าง placeholder wikilink ไปยัง node ที่ยังไม่มี ถ้ายังไม่ควรเป็น node ให้เขียนเป็น plain text
   - ไม่ต้องลิงก์ทุกอย่างเข้าหากัน เลือกเฉพาะความสัมพันธ์ที่มีความหมาย เพื่อไม่ให้กราฟรก
   - backlink สองทางไม่บังคับ เพราะ Obsidian แสดง edge ได้จากลิงก์ทางเดียว แต่ให้เติมกลับเมื่อช่วยให้ค้นจากอีกฝั่งได้จริง
   - เส้นกราฟใน Obsidian มาจากตรงนี้ node กำพร้าคือ node ที่ไม่มี edge จริง
6. **หลังเขียน**: รัน `bin/sb-link-check.sh <ไฟล์ node ที่สร้างหรือแก้ทั้งหมด>` ก่อน แล้วจึง
   `bin/sb-commit.sh "<op>: <msg>"` เสมอ โดย `sb-commit.sh` จะตรวจซ้ำ บังคับ raw เป็น
   `processed` + มี citation สร้าง `index.md` ใหม่ และ commit ให้อัตโนมัติ

## เส้นแบ่งที่ตัดสินยากบ่อย

- คนดัง/ผู้เชี่ยวชาญที่เราไม่รู้จักตัวจริง → `entities/` · คนที่เจอ/คุย/มี contact → `people/`
- "สรุปทุกอย่างเกี่ยวกับ X" → `concepts/` · "X กับ Y อันไหนดีกว่า" → `comparisons/` ·
  "คำถามที่เราถามแล้วได้คำตอบ" → `queries/`
- ถ้ายังก้ำกึ่งจริงๆ → `concepts/` (default ที่ปลอดภัยสุด) แล้วโน้ตไว้ใน node ว่าอาจย้าย
